# 나만의 프롬프트 관리 프로그램

Python과 Git을 활용하여 제작한 콘솔 기반 프롬프트 관리 프로그램입니다.

이전 미션에서 제작한 프롬프트를 한곳에서 관리할 수 있도록 프롬프트 추가, 목록 조회, 카테고리별 조회, 검색, 상세 보기, 즐겨찾기 기능을 구현했습니다.

Git을 활용하여 기능 단위로 변경 사항을 커밋하고 GitHub 저장소를 통해 프로젝트의 버전과 변경 이력을 관리했습니다.

## 3. 기능 목록

### 3.1 프롬프트 추가

새로운 프롬프트를 등록할 수 있습니다.

입력 항목은 다음과 같습니다.

- 제목
- 내용
- 카테고리

제목, 내용, 카테고리가 비어 있는 경우 다시 입력하도록 처리했습니다.

새롭게 추가된 프롬프트의 즐겨찾기 상태는 기본적으로 `False`로 설정됩니다.

### 3.2 프롬프트 목록

등록된 모든 프롬프트를 번호와 함께 출력합니다.

각 프롬프트에 다음 정보를 표시합니다.

- 번호
- 카테고리
- 제목
- 즐겨찾기 여부

즐겨찾기로 설정된 프롬프트에는 `⭐` 표시가 나타납니다.

### 3.3 카테고리별 조회

미리 정의된 카테고리를 선택하여 해당 카테고리의 프롬프트만 조회할 수 있습니다.

선택한 카테고리와 프롬프트의 `category` 값을 비교하여 해당 카테고리의 데이터만 출력합니다.

해당 카테고리에 프롬프트가 없는 경우 안내 메시지를 출력합니다.

### 3.4 프롬프트 검색

검색어를 입력하여 프롬프트를 검색할 수 있습니다.

검색 대상은 다음과 같습니다.

- 프롬프트 제목
- 프롬프트 내용

입력한 검색어가 제목 또는 내용에 포함되어 있는지 확인하는 부분 문자열 검색 방식을 사용합니다.

대소문자 차이를 무시하기 위해 `lower()`를 사용합니다.

검색 결과가 없는 경우 안내 메시지를 출력합니다.

향후 다음과 같은 방식으로 확장할 수 있습니다.

- 여러 키워드 동시 검색
- 카테고리와 키워드를 조합한 검색
- 검색 결과 정렬
- 정규식을 활용한 고급 검색

### 3.5 프롬프트 상세 보기

프롬프트 번호를 입력하면 해당 프롬프트의 상세 내용을 확인할 수 있습니다.

다음 정보를 출력합니다.

- 제목
- 카테고리
- 즐겨찾기 여부
- 프롬프트 내용 전체

입력한 번호가 숫자가 아니거나 등록된 프롬프트의 범위를 벗어난 경우 안내 메시지를 출력합니다.

### 3.6 즐겨찾기 관리

프롬프트 번호를 입력하여 즐겨찾기를 추가하거나 해제할 수 있습니다.

현재 즐겨찾기 상태가 `False`라면 `True`로 변경하여 즐겨찾기에 추가하고, 이미 `True`라면 `False`로 변경하여 즐겨찾기에서 해제합니다.

즐겨찾기 상태가 변경되면 프롬프트 목록과 상세 보기에서 `⭐` 표시를 확인할 수 있습니다.

### 3.7 즐겨찾기 목록

등록된 프롬프트 중 즐겨찾기 상태가 `True`인 프롬프트만 모아서 출력합니다.

즐겨찾기한 프롬프트가 없는 경우 안내 메시지를 출력합니다.

## 6. 데이터 구조

프롬프트 데이터는 Python의 리스트와 딕셔너리를 사용하여 관리합니다.

```python
prompts = [
    {
        "title": "로판 캐릭터 이미지 생성",
        "content": "로맨스 판타지풍의 캐릭터를 생성해주세요.",
        "category": "이미지 생성",
        "favorite": False
    }
]
```

각 프롬프트는 다음과 같은 필드를 가지고 있습니다.

| 필드 | 자료형 | 설명 |
|---|---|---|
| `title` | `str` | 프롬프트 제목 |
| `content` | `str` | 프롬프트 내용 |
| `category` | `str` | 프롬프트 카테고리 |
| `favorite` | `bool` | 즐겨찾기 여부 |

### 리스트를 사용하는 이유

여러 개의 프롬프트를 순서대로 저장하고 반복문을 사용하여 전체 데이터를 쉽게 조회할 수 있기 때문에 리스트를 사용했습니다.

### 딕셔너리를 사용하는 이유

하나의 프롬프트가 가지고 있는 제목, 내용, 카테고리, 즐겨찾기 여부를 각각의 키와 값으로 명확하게 관리할 수 있기 때문에 딕셔너리를 사용했습니다.

### 장점

- Python 기본 자료형만으로 구현할 수 있습니다.
- 구조가 단순하여 이해하기 쉽습니다.
- 프롬프트의 추가와 조회가 간단합니다.
- 기능별로 데이터를 처리하기 쉽습니다.

### 한계

현재 데이터는 프로그램 실행 중 메모리에 저장됩니다.

따라서 프로그램을 종료하면 새롭게 추가한 프롬프트와 변경한 즐겨찾기 상태가 초기화됩니다.

추후 JSON 파일이나 데이터베이스를 활용하면 데이터를 영구적으로 저장할 수 있습니다.

## 7. 입력 검증

사용자의 잘못된 입력으로 프로그램이 중단되지 않도록 기본적인 입력 검증을 적용했습니다.

### 문자열 입력

프롬프트 추가 시 제목, 내용, 카테고리가 비어 있는지 확인합니다.

```python
if not title:
    print("제목을 입력해주세요.")
```

입력값이 비어 있으면 다시 입력하도록 처리합니다.

### 숫자 입력

프롬프트 번호를 입력받는 기능에서는 `isdigit()`을 사용하여 숫자 여부를 확인합니다.

```python
if not number.isdigit():
    print("올바른 번호를 입력해주세요.")
```

또한 입력된 번호가 실제 등록된 프롬프트의 범위에 포함되는지도 확인합니다.

### 메뉴 입력

메뉴에 존재하지 않는 번호를 입력한 경우 잘못된 선택이라는 안내 메시지를 출력합니다.

## 8. 코드 구조

프로그램의 모든 기능을 하나의 함수에 작성하지 않고 기능별로 함수를 분리했습니다.

| 함수 | 역할 |
|---|---|
| `show_menu()` | 프로그램 메뉴 출력 및 기능 선택 |

| `show_detail()` | 프롬프트 상세 내용 출력 |
| `toggle_favorite()` | 즐겨찾기 추가 및 해제 |
| `show_favorites()` | 즐겨찾기 프롬프트만 출력 |

각 함수는 하나의 기능을 담당하도록 분리하여 코드의 가독성과 유지보수성을 높였습니다.

## 9. 메뉴 반복 구조

프로그램은 `while` 반복문을 사용하여 메뉴를 반복해서 출력하도록 구성했습니다.

기본적인 실행 흐름은 다음과 같습니다.

```text
프로그램 시작
    ↓
메뉴 출력
    ↓
사용자 선택
    ↓
선택한 기능 실행
    ↓
다시 메뉴 출력
    ↓
사용자 선택
    ↓
...
    ↓
0 선택
    ↓
프로그램 종료
```

하나의 기능을 실행한 후에도 프로그램을 종료하지 않고 다른 기능을 계속 사용할 수 있도록 메뉴를 반복합니다.

`0`을 입력하면 반복문을 종료하고 프로그램을 종료합니다.

## 10. 입력 데이터 중복 처리

현재 프로그램에서는 동일한 제목이나 동일한 카테고리를 가진 프롬프트의 등록을 허용합니다.

각 프롬프트는 리스트에 별도의 데이터로 저장되며, 목록에 표시되는 번호를 통해 구분합니다.

현재 버전에서는 데이터 입력 구조를 단순하게 유지하기 위해 중복 등록을 별도로 제한하지 않았습니다.

향후 개선 시 다음과 같은 방식으로 중복 데이터를 관리할 수 있습니다.

- 동일한 제목 등록 제한
- 동일한 제목 입력 시 등록 여부 확인
- 중복 제목에 번호 추가
- 고유 ID를 부여하여 프롬프트 구분

## 11. 데이터 저장 방식

현재 프로그램은 실행 중인 메모리에 프롬프트 데이터를 저장합니다.

따라서 프로그램 실행 중에는 추가 및 변경된 데이터가 유지되지만 프로그램을 종료하면 초기화됩니다.

이는 이번 미션의 기본 구현 범위에 맞춘 방식입니다.

향후 데이터 영속화가 필요한 경우 JSON 파일 저장 방식을 적용할 수 있습니다.

### JSON 저장 방식의 장점

- 별도의 데이터베이스가 필요하지 않습니다.
- Python에서 쉽게 읽고 쓸 수 있습니다.
- 현재 리스트와 딕셔너리 구조를 유지하면서 확장할 수 있습니다.

추가적으로 SQLite 등의 데이터베이스를 사용하면 데이터가 많아졌을 때 더욱 체계적으로 관리할 수 있습니다.

## 12. Git 사용

프로젝트의 코드 변경 이력을 관리하기 위해 Git을 사용했습니다.

### 주요 Git 명령어

| 명령어 | 역할 |
|---|---|
| `git init` | 로컬 저장소 초기화 |
| `git add` | 변경된 파일을 스테이징 영역에 추가 |
| `git commit` | 변경 사항을 커밋으로 저장 |
| `git push` | 로컬 커밋을 GitHub에 업로드 |
| `git pull` | 원격 저장소의 변경 사항 가져오기 |
| `git clone` | 원격 저장소를 로컬로 복제 |
| `git checkout` | 브랜치 전환 |
| `git merge` | 브랜치의 변경 사항 병합 |

### 커밋 기준

기능이 하나씩 완성될 때마다 기능 단위로 커밋했습니다.

예시:

```text
카테고리별 조회 기능 구현
프롬프트 검색 기능 구현
프롬프트 상세 보기 기능 구현
즐겨찾기 관리 기능 구현
```

커밋 메시지를 기능 중심으로 작성하여 각 커밋에서 어떤 변경이 이루어졌는지 확인할 수 있도록 했습니다.

## 13. 브랜치 활용

기능 개발 과정에서 `main` 브랜치와 별도의 작업 브랜치를 분리하여 사용할 수 있도록 Git 브랜치 기능을 활용했습니다.

기본적인 작업 흐름은 다음과 같습니다.

```text
main
 ↓
작업 브랜치 생성
 ↓
기능 구현
 ↓
commit
 ↓
main 브랜치 checkout
 ↓
merge
 ↓
main에 기능 반영
```

브랜치를 사용하는 이유는 새로운 기능을 개발하는 동안 기존의 안정적인 `main` 브랜치와 작업 내용을 분리하기 위해서입니다.

기능 개발과 테스트가 완료된 후 `main` 브랜치에 병합하여 최종 코드를 관리합니다.

## 14. 샘플 저장소 Clone

Git의 `clone` 기능을 학습하기 위해 공개 샘플 저장소를 로컬 환경에 복제하고 폴더 구조와 Git 로그를 확인했습니다.

사용한 명령어 형식은 다음과 같습니다.

```bash
git clone [샘플 저장소 URL]
```

Clone한 저장소의 파일 구조와 커밋 기록을 확인한 후 필요하지 않은 샘플 저장소는 삭제했습니다.
